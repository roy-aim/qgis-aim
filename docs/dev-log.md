# Log Pengembangan AIM Editor (QGIS Plugin)

Dokumen ini mencatat ringkasan pekerjaan yang telah dilakukan pada proyek plugin QGIS **AIM Editor**, dikelompokkan per tanggal dan kontributor. Formatnya mengikuti `aim-dev-log-summary.md` di repositori `backend-aim`/`web-aim`, namun karena proyek ini lebih kecil dan belum ada kode produksi, entrinya cukup satu tingkat ringkasan (tidak ada dev-log versi detail terpisah).

---

## 2026-09-09

### Roy

- **Backend (`backend-aim`) Tahap 3-5 Selesai & Terverifikasi End-to-End** — user menjalankan skrip Tahap 3 (`CREATE ROLE qgis_writer_apron_taxiway` + `GRANT`) dan Tahap 4 (RLS) manual di database dev. Ditemukan & diperbaiki 2 bug lewat percobaan langsung: (1) tabel `adhp`/`ADHPSurfaceArea` ternyata di schema `app_user`, bukan `public` — field `schema` baru ditambahkan ke response `GET /db-credentials`, `api_client.py` (`DbCredentials`) disesuaikan; (2) `ADHPSurfaceArea` dan kolomnya dibuat tanpa tanda kutip di migration backend sehingga case-folded ke lowercase (`adhpsurfacearea`, `subtype_code`) — semua skrip SQL backend yang salah pakai kutip diperbaiki. RLS diverifikasi lewat `psql` langsung (role backend tetap lihat semua subtype, role plugin cuma lihat Apron, akses tabel `users` ditolak). Role aplikasi `qgis_editor_apron_taxiway` di-assign manual ke user seed `ad_editor`; endpoint `GET /db-credentials` diverifikasi end-to-end via `curl` (login → token → `200 OK` dengan kredensial lengkap; user tanpa permission → `403`). Backend sekarang sepenuhnya siap dipakai plugin — sisi plugin sendiri (Tahap 3-4 di `implementation-plan.md`, `layer_manager.py`/`adhp_search_dialog.py`) masih belum ditulis.

## 2026-09-08

### Roy

- **Dokumen Arsitektur Awal + Skeleton Plugin** — `business-rules.md` dan `implementation-plan.md` ditulis dari hasil diskusi arsitektur sebelumnya: login plugin ke REST API existing (PASETO) untuk dapat kredensial PostgreSQL per kelompok hak akses (bukan shared account), disimpan lewat `QgsAuthManager` (bukan plaintext), editing geometri native QGIS↔PostGIS dengan proteksi sesungguhnya di level DB (RLS + grant per role). Skeleton awal kode (`api_client.py`, `auth_manager.py`, `login_dialog.py`, `__init__.py`, `metadata.txt`) dibuat berdasarkan asumsi skema sederhana (`airport`/`apron`/`taxiway`).
- **Keputusan Tambahan: Concurrent Edit & Distribusi Plugin** — last-write-wins dipilih untuk penanganan edit bersamaan (selaras dengan cara kerja native QGIS editing, bukan row-level lock Postgres). Distribusi plugin lewat QGIS Plugin Repository kustom (`plugins.xml` + GitHub Releases dari repo publik), bukan mekanisme self-update kustom (pertimbangan permukaan serangan).
- **Riset Skema Backend Nyata → Revisi Total Dokumen** — riset langsung ke repo `backend-aim` (Go/Gin/pgx) menemukan skema data GIS **bukan** tabel sederhana `airport`/`apron`/`taxiway` seperti asumsi awal, melainkan model AIS/ICAO: parent = tabel `adhp` (PK `gfid` VARCHAR(38)), dan Apron/Taxiway bukan tabel terpisah melainkan baris di tabel `ADHPSurfaceArea` yang dibedakan kolom `SUBTYPE_CODE` (10 subtipe, dikonfirmasi user hanya `SUBTYPE_CODE` 6=Taxiway dan 8=Apron yang masuk cakupan rilis awal). Dikonfirmasi juga: database GIS satu instance sama dengan database otorisasi backend (`aimdb`), tidak ada RLS maupun trigger audit existing sama sekali di database ini. `business-rules.md` dan `implementation-plan.md` dirombak total mengikuti skema nyata ini; `api_client.py`/`login_dialog.py`/`auth_manager.py` disesuaikan (field request/response REST, method `get_me()` menggantikan asumsi `get_my_rights()`).
- **Role & Permission Aplikasi Khusus untuk Plugin** — diputuskan plugin memakai role/permission aplikasi baru yang khusus (`qgis-apron-taxiway:read`/`update`, role `qgis_editor_apron_taxiway`/`qgis_viewer_apron_taxiway`), bukan menumpang pada `runway:*`/`admin_aerodrome`/`editor_aerodrome` existing yang cakupannya lebih luas. Dokumen aturan bisnis dan rencana implementasi sisi backend (permission/role baru, endpoint `GET /db-credentials`, grant PostgreSQL, RLS berbasis `SUBTYPE_CODE`) ditulis terpisah di repo `backend-aim` (`docs/aim-pages/qgis-support/qgis-be-business-rules.md` dan `qgis-be-implementation-plan.md`, mengikuti konvensi penamaan dokumen modul mereka), bukan di repo ini — dokumen `qgis-aim` di-cross-reference ke situ tanpa duplikasi detail.
- **Repo GitHub Dibuat, Klarifikasi Model Visibilitas, Push Pertama** — dijelaskan model visibilitas dua lapisan: source code + rilis `.zip` publik di GitHub (aman karena tidak ada secret di kode), tapi plugin tidak didaftarkan ke katalog resmi QGIS.org sehingga tidak "ditemukan" pasif — kontrol akses sesungguhnya tetap di lapisan otorisasi (butuh akun REST API organisasi). Ditambahkan klarifikasi ini ke `business-rules.md` Bagian 8. Repo `git@github.com:roy-aim/qgis-aim.git` dibuat (publik, kosong), `.gitignore` disiapkan, commit pertama (dokumen + skeleton kode) berhasil di-push ke `main`.
- **README.md Ditambahkan** — gambaran umum plugin, status pengembangan, cakupan rilis, dan tautan ke dokumentasi. Bagian instalasi sengaja dibiarkan placeholder (menunggu Tahap 8 selesai) untuk menghindari instruksi yang belum sungguhan berlaku. `metadata.txt` dilengkapi field `repository`/`tracker`/`homepage` yang mengarah ke repo GitHub.
- **Tahap 1 Selesai: Skeleton `main_plugin.py`** — kelas `AimEditorPlugin` dengan `initGui()`/`unload()` standar QGIS, satu tombol toolbar+menu placeholder belum terhubung logic bisnis. Diuji langsung di QGIS Desktop lewat symlink dari folder plugins QGIS ke repo (bukan copy manual, supaya perubahan kode langsung reflect saat development) — plugin aktif tanpa error, tombol berfungsi menampilkan pesan info yang sesuai. Tahap 1 diverifikasi selesai.
- **Backend (`backend-aim`) Tahap 1-2 Selesai: Seeder Permission/Role + Endpoint `/db-credentials`** — mode baca-saja rilis awal diputuskan ditunda (cukup 1 role `qgis_editor_apron_taxiway`/`qgis_writer_apron_taxiway`, bukan 2). Seeder Go baru (`cmd/seeder/app/seed_qgis_permissions.go`, mengikuti pola persis `seed_runway_permissions.go`) menambahkan permission `qgis-apron-taxiway:update` dan role `qgis_editor_apron_taxiway` (didaftarkan ke `roles.go` lebih dulu supaya `associatePermissions` tidak skip). Modul `internal/dbcredentials/` baru: `GET /db-credentials` memetakan permission tsb ke kredensial role PostgreSQL `qgis_writer_apron_taxiway`, host/port/dbname di-derive dari `DATABASE_URL` yang sama (bukan koneksi DB terpisah — modul ini tidak connect ke database sama sekali, murni baca env var `QGIS_WRITER_APRON_TAXIWAY_DB_PASSWORD` baru), proteksi permission lewat middleware existing (pola sama `adhp`/`runway`). Ditemukan dan diperbaiki sekalian bug pre-existing tidak terkait (`wire.go` kehilangan binding `referencepoint.DBPool`, bikin `make wire` gagal untuk seluruh modul — dikonfirmasi via `git stash` bukan disebabkan perubahan ini). Dokumen API baru `docs/aim-api/qgis_db_credentials.md` (backend-aim) ditambahkan mengikuti format existing. `go build`/`go vet` seluruh proyek bersih. Belum diverifikasi end-to-end (butuh `make seed` + isi password env var + role PostgreSQL dari Tahap 3 dibuat manual).
- **Dev-Log Backend Sempat Terlewat + Push Konflik Rebase** — entri dev-log detail/summary di `backend-aim` (`aim-dev-log.md`/`aim-dev-log-summary.md`) sempat tidak ter-commit bareng kode Tahap 1-2, diperbaiki lewat commit terpisah. Saat push ke `origin/main`, ada 2 commit baru dari kolaborator lain (modul `obstacle`) — di-rebase (bukan merge), satu konflik nyata di `internal/server/dependencies.go` (commit remote menghapus mekanisme `obstacle.CoordinateParser` yang jadi kode mati kalau tidak ikut dibersihkan) berhasil diresolve tanpa kehilangan perubahan siapa pun, `go build`/`go vet`/`make wire` diverifikasi ulang setelah rebase sebelum push.
- **Role Postgres Dijalankan User, Ditemukan 2 Bug Nyata Lewat Percobaan Langsung** — (1) tabel `adhp`/`ADHPSurfaceArea` ternyata **tidak** berada di schema `public` (mengikuti nama user koneksi database) — ditambahkan field `schema` baru ke response `GET /db-credentials` (env var backend baru `QGIS_APRON_TAXIWAY_DB_SCHEMA`), `DbCredentials` di `api_client.py` disesuaikan. (2) Tabel `ADHPSurfaceArea` dan seluruh kolomnya dibuat **tanpa tanda kutip** di migration backend, sehingga PostgreSQL otomatis fold ke huruf kecil (`adhpsurfacearea`, `subtype_code`, dst) — semua skrip SQL (GRANT Tahap 3, RLS Tahap 4, `APP_README.md`) yang sebelumnya salah menulis `"ADHPSurfaceArea"`/`"SUBTYPE_CODE"` dengan kutip diperbaiki jadi tanpa kutip, dikonfirmasi lewat error nyata (`relation ... does not exist`) yang hilang setelah kutip dihapus. Kedua temuan dicatat sebagai peringatan eksplisit di `implementation-plan.md` Tahap 3-4 dan docstring `api_client.py` supaya tidak terulang saat `layer_manager.py` benar-benar ditulis.
