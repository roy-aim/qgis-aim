# Log Pengembangan AIM Editor (QGIS Plugin)

Dokumen ini mencatat ringkasan pekerjaan yang telah dilakukan pada proyek plugin QGIS **AIM Editor**, dikelompokkan per tanggal dan kontributor. Formatnya mengikuti `aim-dev-log-summary.md` di repositori `backend-aim`/`web-aim`, namun karena proyek ini lebih kecil dan belum ada kode produksi, entrinya cukup satu tingkat ringkasan (tidak ada dev-log versi detail terpisah).

## 2026-09-09 (lanjutan lagi — koreksi & fitur editing tambahan)

### Roy

Lanjutan sesi sebelumnya, banyak koreksi & fitur baru hasil testing manual GUI berulang (via QGIS MCP untuk verifikasi cepat, testing manual user untuk konfirmasi visual akhir):

- **Konfirmasi sebelum ganti bandara/login ulang saat sesi editing aktif** — bug nyata: pindah bandara di tengah sesi editing (layer `isEditable()` + ada perubahan uncommitted) bikin zoom/filter "ngaco" (root cause: `setSubsetString()` ganti filter di layer yang sama sementara ada perubahan belum di-commit, state layer/kanvas jadi ga konsisten — QGIS ga didesain buat ganti subset filter di tengah sesi edit aktif). Ditambahkan `_confirm_end_editing()` di `main_plugin.py`: cek layer Apron/Taxiway yang `isEditable() and isModified()`, kalau ada tampilkan dialog Simpan/Buang/Batal SEBELUM lanjut. Dipanggil di `run()` (sebelum login ulang) dan `_open_apron_taxiway()` (sebelum buka dialog search bandara, supaya user ga buang waktu cari bandara baru kalau ujungnya batal).
- **Zoom kanvas ke bandara dengan 2 kondisi** — request awal: kalau bandara belum ada geometri Apron/Taxiway, zoom ke titik ARP; kalau sudah ada, zoom ke extent gabungan Apron+Taxiway. Buffer titik ARP diperkecil dari 0.05° ke 0.01° (kejauhan untuk bandara ukuran sedang).
- **Bug nyata: zoom "aneh" pas pindah ke WIII** — extent gabungan melebar dari Sumatera sampai Jakarta. Diinvestigasi lewat MCP: BUKAN bug kode zoom (extent & transform CRS sudah benar), melainkan **data salah** — fitur "Apron A" punya `adhp_id` WIII tapi geometrinya digambar di lokasi WITT (sisa testing manual sebelumnya). Dikonfirmasi user untuk tidak menyentuh data (kecuali geometri fitur ini), di-null-kan geometrinya (`changeGeometry(feat_id, QgsGeometry())`, baris/atribut tetap ada) lewat MCP atas persetujuan user.
- **Tombol "Kosongkan Geometri Fitur Terpilih"** — QGIS tidak punya cara GUI standar untuk mengosongkan geometri fitur TANPA menghapus baris (tombol Delete keyboard selalu hapus seluruh fitur, dikonfirmasi lewat percobaan manual user). Action baru di `main_plugin.py`/`_clear_selected_geometries()`: cek layer aktif adalah layer plugin, cek mode editing aktif, cek ada seleksi, lalu `changeGeometry()` ke geometri kosong untuk semua fitur terpilih (belum auto-commit, user tetap kontrol lewat Save Edits/Toggle Editing biasa).
- **Tombol "Timpakan Geometri ke Baris Terpilih"** — kebalikannya: mengisi geometri ke baris existing yang masih NULL (skenario record sudah dibuat, geometri baru digambar belakangan). QGIS juga tidak punya tool bawaan untuk "gambar geometri lalu tempelkan ke fitur existing" (dikonfirmasi lewat riset API `qgis.gui`) — alur: user gambar geometri baru (jadi fitur sementara), select 2 fitur (baris lama NULL + fitur baru), klik tombol, plugin pindahkan geometri via `changeGeometry()` lalu `deleteFeature()` fitur sementara. Atribut baris lama (name_txt, status_code, dst) tidak disentuh sama sekali.
- **Koreksi: `type_code` Apron wajib NULL** (bukan fixed `'APRON'` seperti keputusan sebelumnya) — field dihilangkan total dari form Apron (`_field_order_for_subtype()` baru, exclude `type_code` khusus Apron), default value diubah ke ekspresi `"NULL"` (`applyOnUpdate=True`) supaya tetap eksplisit ke-NULL-kan saat commit meski field tidak pernah dirender di form. Taxiway tidak berubah (tetap combobox ValueMap). 5 baris Apron existing yang masih `type_code='APRON'` (sisa testing lama) di-update ke NULL via MCP atas instruksi user.
- **Bug nyata: `designator_txt` tidak ke-set** — field punya logic `QgsDefaultValue` sejak awal tapi tidak pernah ditambahkan ke daftar field form (`SURFACE_AREA_FIELD_ORDER_TOP`), jadi default value-nya tidak pernah ter-trigger karena field-nya sendiri tidak pernah dirender form (form sudah difilter, hanya render field yang eksplisit terdaftar). Diperbaiki: ditambahkan ke list, persis di bawah `name_txt`, read-only (bukan editable seperti draft awal).
- **Bug nyata: dialog error login muncul 2x identik** — root cause race condition Qt: tombol OK `LoginDialog` di-enable SEBELUM `QMessageBox.critical()` ditutup, jendela waktu kecil bikin mouse-release event dari klik OK di message box "leak" ke tombol OK dialog login yang sudah aktif lagi di belakangnya, trigger ulang `_on_login_clicked()` dengan kredensial sama. Diperbaiki: `buttons.setEnabled(True)` dipindah ke SETELAH `QMessageBox.critical()` selesai.
- **Fokus awal form login ke Username/Email** — `LoginDialog.showEvent()` override baru, `setFocus()` ke `login_id_edit` tiap kali dialog muncul (server URL jarang perlu diganti tiap login).
- **Label kanvas** — fitur Apron/Taxiway sekarang berlabel `name_txt` di kanvas (`_apply_name_label()`, `QgsPalLayerSettings`+`QgsVectorLayerSimpleLabeling`), biar user langsung lihat nama fitur tanpa buka form/attribute table.
- **Attribute Table disamakan dengan form** — defaultnya Attribute Table QGIS selalu menampilkan SEMUA kolom skema (>40) apa adanya, beda dari form yang sudah difilter/diurutkan. Ditambahkan `_apply_attribute_table_config()` (pakai `QgsAttributeTableConfig`) yang menyembunyikan kolom yang tidak ada di daftar form, dengan urutan yang sama.
- **Kolom `shape_status` (Ada/Kosong) di Attribute Table** — kolom geometri (`shape`) bukan field/atribut biasa (dipisah provider PostGIS lewat `setDataSource()`), tidak bisa ditampilkan langsung sebagai kolom teks. Ditambahkan expression field virtual (`QgsVectorLayer.addExpressionField()`, ekspresi `CASE WHEN $geometry IS NULL THEN 'Kosong' ELSE 'Ada' END`), idempotent (cek nama field dulu sebelum nambah, supaya tidak numpuk tiap ganti bandara), ditaruh di kolom paling akhir Attribute Table — memudahkan user cek baris mana yang masih perlu digambar geometrinya.
- **Backend (`backend-aim`) — Grant SELECT ke tabel domain dijalankan user**, diverifikasi combobox `status_code`/`abandoned_code` bekerja dengan data domain asli (lihat entri backend-aim hari yang sama).

Fix: helper `_transform_extent()` pakai `QgsCoordinateTransform`, baca CRS kanvas secara dinamis (robust walau CRS project diganti). Dikonfirmasi via screenshot MCP setelah fix: citra satelit + geometri Apron/Taxiway WIII tampil normal.
